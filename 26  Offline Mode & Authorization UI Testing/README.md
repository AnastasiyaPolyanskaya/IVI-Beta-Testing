# 26 - Offline Mode & Authorization UI Testing

Практический проект по ручному тестированию мобильного приложения IVI.

В рамках проекта проведено тестирование экранов офлайн-режима, процесса обновления приложения, экрана авторизации и настроек уведомлений после внутренних изменений и обновлений пользовательского интерфейса.

---

## Цель проекта

Проверить корректность отображения новых экранов, стабильность работы приложения после обновления и правильность работы элементов интерфейса в различных пользовательских сценариях.

---

## Объект тестирования

Мобильное приложение IVI

- Платформа: iOS
- Тип тестирования: Manual QA

---

## Области тестирования

### 1. Экран авторизации

Проверено:

- отображение юридических документов на узбекском языке;
- корректность переноса строк;
- экран ввода кода подтверждения;
- экран установки и ввода PIN-кода.

**Ожидаемый результат:**

- элементы интерфейса соответствуют макетам;
- перенос текста отображается корректно.

---

### 2. Обновление приложения

Проверено:

- обновление со старой версии приложения;
- запуск приложения после обновления;
- восстановление работы после отключения и повторного включения сети.

**Ожидаемый результат:**

- главная и остальные экраны загружаются корректно.

---

### 3. Новый экран загрузок в офлайн-режиме

Проверено:

- отображение экрана при отсутствии скачанного контента;
- отображение экрана при наличии загруженного контента;
- корректность отображения элементов интерфейса.

**Ожидаемый результат:**

- экран соответствует утвержденным макетам.

---

### 4. Экран-заглушка в офлайн-режиме

Проверено:

- отображение заглушки без скачанного контента;
- отображение заглушки при наличии скачанного контента;
- корректность отображения на различных экранах приложения.

**Ожидаемый результат:**

- экран соответствует дизайн-макетам.

---

### 5. Настройки уведомлений

Проверено:

- отображение пунктов управления уведомлениями;
- скрытие недоступных настроек при отсутствии привязанного номера телефона или электронной почты.

**Ожидаемый результат:**

- пользователю отображаются только доступные настройки.

---

### 6. Экран ввода кода

Проверено:

- отображение экрана ввода кода подтверждения;
- отображение экрана ввода PIN-кода;
- соответствие интерфейса утвержденному дизайну.

**Ожидаемый результат:**

- экран соответствует актуальному макету.

---

## Особенности тестирования

Тестирование включало:

- проверку офлайн-режима;
- обновление приложения со старой версии;
- тестирование локализации;
- проверку настроек уведомлений;
- проверку экранов авторизации;
- проверку пользовательского интерфейса.

---

## Результаты тестирования

В ходе тестирования были проверены:

- новый экран загрузок;
- офлайн-заглушки;
- обновление приложения;
- локализация экрана авторизации;
- настройки уведомлений;
- экран ввода кода.

Выявленные дефекты фиксируются в разделе **bug-reports**.

Репозиторий содержит:

## Вывод

Проект направлен на проверку стабильности работы приложения после внутренних изменений, связанных с офлайн-режимом, обновлением интерфейса и экранами авторизации.

Особое внимание уделено:

- работе приложения без сети;
- корректности обновления приложения;
- локализации интерфейса;
- отображению экранов авторизации;
- настройкам уведомлений;
- соответствию интерфейса дизайн-макетам.
